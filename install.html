Installation

Get AI4BayesCode running.

Two steps: install the skill in your coding agent, where samplers are generated, then install the R or Python package, where you run them.

Step 1 · Generate
Coding agent skill

Describe your model in plain language. The agent writes the sampler and validates it, or designs a new block when none fits. Runs on your coding agent subscription.
→
Step 2 · Run
R or Python package

Load the generated sampler, run the chains, and check convergence from R or Python.
1

Step 1 · Generate

Install the skill in your coding agent

AI4BayesCode runs through a coding agent, for example Claude Code, Cursor, or Codex. A chat-only LLM like ChatGPT can’t be used, because the agent needs to work with files on your computer and run code to validate the sampler it builds.

The repository root is the skill package. Install it once, reload, then launch it and describe your model.

Claude Code
# install, or update for new version
git init -q "$HOME/.claude/skills/AI4BayesCode"; git -C "$HOME/.claude/skills/AI4BayesCode" pull -q --ff-only https://github.com/zjg540066169/AI4BayesCode.git main

Restart Claude Code, then type /AI4BayesCode.

Codex
# install, or update for new version
git init -q "$HOME/.agents/skills/AI4BayesCode"; git -C "$HOME/.agents/skills/AI4BayesCode" pull -q --ff-only https://github.com/zjg540066169/AI4BayesCode.git main

Restart Codex, then type /Ai4bayescode (Codex lowercases the skill name, so only the first letter is capitalized).

Other coding agent
# clone the repo (no skills dir needed)
git clone https://github.com/zjg540066169/AI4BayesCode.git

# then tell your coding agent:
Read AI4BayesCode/start.md first,
then: <your model description>

No slash command needed. Cursor, Windsurf, Cline, aider, or any coding agent (one with local-file & code access) launches by reading start.md, which routes you to generate-vs-design and loads the rest on demand.

The command is the same on macOS, Linux, and Windows, and it needs git. On Windows, run it in PowerShell. It does not work in Command Prompt. If you use Claude Code or Codex inside WSL, run it inside WSL. If it reports an error, delete the folder and run it again.

No git, or using Command Prompt? Install the R or Python package from Step 2 first. Then one call installs the skill for both Claude Code and Codex, the same way on every system. Run it again to update. 

# in R
AI4BayesCode::ai4bayescode_install_skill()

# in Python
import AI4BayesCode
AI4BayesCode.install_skill()

If you installed AI4BayesCode with the earlier instructions, delete the old AI4BayesCode folder before you install. Codex users should also delete the old copy in .codex/skills, or Codex will show the skill twice.

Then launch it. Use the slash command in Claude Code / Codex, or tell any other coding agent to "Read AI4BayesCode/start.md first". It first asks what you want to do: generate a sampler (compose existing blocks for your model) or design a new block (build a new sampling primitive). Choose generate a sampler, then describe your model in plain typeable text (spell Greek out: beta, sigma): 

# Claude Code: /AI4BayesCode    ·    Codex: /Ai4bayescode
# Cursor / other coding agent: "Read AI4BayesCode/start.md first"
# then choose "generate a sampler", and describe the model:
y ~ N(Xbeta, sigma^2) with Jeffreys prior p(sigma^2) propto 1/sigma^2

The agent writes the sampler as a .cpp file, validates it, and hands it back. You run it in Step 2. The block-design flow is the other path, for building a new sampling primitive when no existing block fits. It runs only in a coding agent.

Step 2 · Run

Install the R or Python package

The package loads the sampler the agent wrote, runs the chains, and checks convergence. It ships self-contained, with the C++ headers inside, so the sampler finds the AI4BayesCode library on its own and you never have to point it at a folder by hand.

On Windows, R needs Rtools for your R version. Python needs the same Rtools, or MSYS2 with its gcc, armadillo, and openblas64 packages.

R
# needs a C++17 compiler + Rcpp, RcppArmadillo
# (on Windows: Rtools for your R version)
remotes::install_github(
  "zjg540066169/AI4BayesCode", subdir = "r-pkg")
# optional: posterior and bayesplot for the diagnostics,
# igraph for plot_dag(), jsonlite for contributed blocks
install.packages(c("posterior", "bayesplot", "igraph", "jsonlite"))

# then run the sampler the agent wrote:
library(AI4BayesCode)
ai4bayescode_source("./generated/MyModel.cpp")   # compile + load
ai4bayescode_doc(MyModel)   # what does the constructor want?
runs <- ai4bayescode_run_chains(
  function(seed) new(MyModel, y, X, rng_seed = as.integer(seed),
                     keep_history = TRUE),
  n_chains = 4, n_burn = 5000, n_keep = 5000)
ai4bayescode_rhat_summary(runs)   # cross-chain R-hat and ESS
Python
# Python >= 3.11, a C++17 compiler, and the Armadillo headers:
#   macOS: brew install armadillo
#   Debian / Ubuntu: apt-get install libarmadillo-dev
#   Windows: Rtools, or MSYS2 (see above)
pip install "git+https://github.com/zjg540066169/AI4BayesCode.git#subdirectory=python"

# then, in Python, run the sampler the agent wrote:
import AI4BayesCode
mod = AI4BayesCode.source("./generated/MyModel.cpp")   # compile + load
AI4BayesCode.doc(mod.MyModel)   # what does the constructor want?
runs = AI4BayesCode.run_chains(
    lambda s: mod.MyModel(y, X, rng_seed=s, keep_history=True),
    n_chains=4, n_burn=5000, n_keep=5000)
AI4BayesCode.rhat_summary(runs)   # cross-chain R-hat and ESS

Replace MyModel with the class name of your sampler and y, X with its data arguments; ai4bayescode_doc() / AI4BayesCode.doc() prints both. To try the package before generating anything, load a built-in example: ai4bayescode_example("GaussianLocationScale"). The tutorial walks through a full run, and the API page lists every function.

Beyond the built-in blocks, you can also use contributed blocks made by other users, which work just like built-in ones. See the Blocks page for the catalogue and how to install them.

Other options

Generate from R or Python, without a coding agent

The package from Step 2 can also generate a sampler itself, in place of Step 1. This route has less support than the coding agent: it has no block-design flow, and it calls the LLM with an API key billed per call instead of your subscription.

R
# httr2 is needed for generate()
install.packages("httr2")

library(AI4BayesCode)
ai4bayescode_set_key("sk-ant-...")   # replace "sk-ant-..." with your own API key
ai4bayescode_generate(
  "y ~ N(Xbeta, sigma^2) with Jeffreys prior p(sigma^2) propto 1/sigma^2")
# or, instead of set_key, pass the key in the call:
# ai4bayescode_generate(
#   "y ~ N(Xbeta, sigma^2) with Jeffreys prior p(sigma^2) propto 1/sigma^2",
#   API_key = "sk-ant-...")
Python
import AI4BayesCode
AI4BayesCode.set_key("sk-ant-...")   # replace "sk-ant-..." with your own API key
AI4BayesCode.generate(
    "y ~ N(Xbeta, sigma^2) with Jeffreys prior p(sigma^2) propto 1/sigma^2")
# or, instead of set_key, pass the key in the call:
# AI4BayesCode.generate(
#     "y ~ N(Xbeta, sigma^2) with Jeffreys prior p(sigma^2) propto 1/sigma^2",
#     API_key="sk-ant-...")

"sk-ant-..." is a placeholder. Replace it with your own LLM provider key (Anthropic or OpenAI). It must be a real API key billed per call (for Anthropic, an sk-ant-api... key), not a subscription token from claude setup-token, which Anthropic no longer allows on the direct API. ai4bayescode_generate() (R) / AI4BayesCode.generate() (Python) uses that key to write the sampler. Set it once with ai4bayescode_set_key() / AI4BayesCode.set_key(), or pass API_key= to generate() directly. For an OpenAI key, pass provider="openai" to set_key(). Then choose an OpenAI model with the LLM argument of generate(). The function ai4bayescode_models() (R) / AI4BayesCode.models() (Python) lists the supported models.

generate() saves the sampler as a .cpp file. From there, run it exactly as in Step 2.

Standalone C++

Pure-C++ users need a C++17 compiler and the Armadillo linear-algebra library, with BLAS and LAPACK. The bundled include/ headers are the rest of the install.
