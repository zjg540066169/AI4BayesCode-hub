Reference

API documentation.

AI4BayesCode has two layers. You drive the package to turn a model description into a compiled sampler. The compiled sampler exposes a small stateful interface you call to run the chain and read it back. The same names work from R and Python.

The package

Five functions take you from a model description to a running sampler: set your key once, generate the sampler, source it to compile, then run. The R names are ai4bayescode_*; the Python module mirrors them under AI4BayesCode.*.

set_key

Store your LLM provider key for the session. Providers are anthropic, openai, and google. Check what is set with key_status() and list the available models with models().

R       ai4bayescode_set_key(key, provider = "anthropic")
Python  AI4BayesCode.set_key(key, provider="anthropic")

generate

Parse and validate the model description, then write a sampler .cpp to output_path. A validate-then-repair loop (up to max_attempts) keeps iterating until the emitted code compiles and passes the checks. Pass API_key here, or set it once with set_key.

R       ai4bayescode_generate(model_description, LLM = "claude-opus-4-8",
          effort = "high", output_path = "./generated", API_key = NULL)
Python  AI4BayesCode.generate(model_description, LLM="claude-opus-4-8",
          effort="high", output_path="./generated", API_key=None)
model_description
Plain-language model spec (text, or a path to a .txt).
LLM, effort
Which model writes the sampler, and how hard it thinks. See models().
output_path
Where the generated .cpp is written.
API_key
Provider key for this call. Optional if you used set_key.

source

Compile the generated .cpp against the bundled library and load it, with no paths to configure. After it returns, the sampler class is available: new(MyModel, ...) in R, mod.MyModel(...) in Python.

R       ai4bayescode_source(code, rebuild = FALSE)
Python  AI4BayesCode.source(code, rebuild=False)

doc

Print a usage card for a compiled sampler: the constructor arguments with their types and defaults, the model description, and the available methods. It answers “what does the constructor want?”.

R       ai4bayescode_doc(MyModel)
Python  AI4BayesCode.doc(MyModel)

example

Compile and load a bundled example by name, a one-line way to see a working sampler. list_examples() shows the full set. Python ships the same examples; load one with source.

R       ai4bayescode_example("GaussianLocationScale")

The generated sampler

Once source (or example) has loaded a sampler class, build it with your data and drive it through a small stateful interface. Every block, every composite, and the top-level sampler expose the same methods, so a composite is indistinguishable from a single block.

constructor

Build the sampler with your data. seed fixes the RNG; keep_history = TRUE records every draw (otherwise only the latest draw is kept). Run doc() to see the exact arguments for your model.

R       m <- new(MyModel, y, X, seed = 1L, keep_history = TRUE)
Python  m = mod.MyModel(y, X, seed=1, keep_history=True)

step

Run n MCMC iterations, advancing the chain in place. Call it repeatedly, for example a burn-in pass followed by a recording pass.

R   m$step(n)          Python   m.step(n)

get_current

The current draw as a named list (R) or dict (Python) of parameter values on the natural scale. Does not advance the chain.

R   m$get_current()    Python   m.get_current()

set_current

Overwrite the current parameter values, to warm-start from a previous run or a user-supplied initial value. Does not reset adaptation.

R   m$set_current(params)    Python   m.set_current(params)

get_history

All stored draws as a named map {parameter: matrix of shape (n_draws x dim)}. With history off, it returns the current draw as a one-row matrix. Feed it straight to ai4b_diagnose().

R   hist <- m$get_history()    Python   hist = m.get_history()

predict_at

Posterior-predictive draws at new inputs, using the recorded chain.

R   m$predict_at(new_data)    Python   m.predict_at(new_data)

readapt_NUTS

Re-tune the NUTS step size and mass matrix without advancing the chain, useful when the target geometry shifts mid-run. NUTS-family blocks only; other blocks are skipped.

R   m$readapt_NUTS()    Python   m.readapt_NUTS()

Diagnostics

After sampling, summarize and check convergence. These ship with the package, so a generated runner calls the same functions by name.

ai4b_diagnose

Model-independent posterior diagnostics from get_history(): a summary table with R-hat and bulk / tail ESS, plus a trace, autocorrelation, and density plot.

R       ai4b_diagnose(hist, plot = TRUE)
Python  AI4BayesCode.ai4b_diagnose(hist)

run_chains

Run several independent chains in parallel and collect them, for cross-chain R-hat and ESS. Companions: AI4BayesCode_rhat_summary() in R; rhat(), ess_bulk(), ess_tail() in Python.

R       AI4BayesCode_run_chains(model_ctor, ...)
Python  AI4BayesCode.run_chains(factory, ...)
